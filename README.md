# مسعّر بيت القصيد — نظام إدارة عروض الأسعار (المرحلة الأولى)

## التشغيل المحلي

```bash
npm install
npx playwright install chromium   # مرة واحدة فقط — متصفح داخلي لتصدير PDF
npx tsx src/lib/db/seed.ts        # بيانات تجريبية أولية (مرة واحدة فقط؛ يتجاهل نفسه إن كانت القاعدة معبأة)
npm run dev                       # وضع التطوير — http://localhost:3000
# أو للتشغيل الفعلي:
npm run build && npm run start
```

يتطلب Node.js 22 أو أحدث (لاستخدام `node:sqlite` المدمجة). قاعدة البيانات ملف SQLite وحيد في `data/app.db` — لا حاجة لأي خادم قاعدة بيانات خارجي.

## ما الذي تم بناؤه

النطاق الكامل المطلوب في برومبت المرحلة الأولى: تسجيل دخول وصلاحيات على مستوى الخادم، عملاء ومشاريع، مكتبة فقرات مركزية (بلقطة/snapshot عند الإضافة لا تتأثر بتعديلات لاحقة على المكتبة)، محرك تسعير Markup-on-Cost، محرر تندر كامل (أقسام/فقرات، فقرات مخصصة، إعادة ترتيب، إخفاء فقرة عن العميل)، دورة مراجعة واعتماد كاملة مع سجل زمني، معاينة داخلية/عميل منفصلتين، تصدير PDF عربي RTL احترافي مع علامة "مسودة" المائية قبل الاعتماد، إعدادات شركة، ترقيم تلقائي متسلسل للعروض، لوحة تحكم وبحث وفلاتر، وبيانات تجريبية واقعية.

## نقطة تحتاج تأكيدك

جميع الأدوار الثلاثة (مسؤول النظام، المدير، معدّ التندر) تستطيع حالياً رؤية الكلفة وهامش الربح داخل محرر التندر، لأن معدّ التندر قد يحتاج إدخال الكلفة أثناء الإعداد. فقط المدير ومسؤول النظام يمكنهما تعديل الخصم أو السعر اليدوي. إن كنت تريد إخفاء الكلفة/الربح عن معدّ التندر بالكامل (وعرضهما فقط بعد أن يُدخل الكلفة دون رؤية الربح المحسوب)، أخبرني لأعدّل الصلاحيات.

## تبسيطات مقصودة (للمرحلة الأولى فقط)

- إعادة ترتيب الأقسام/الفقرات بأزرار ▲▼ بدل السحب والإفلات الكامل (drag-and-drop) — أسرع وأضمن حالياً؛ يمكن إضافة السحب والإفلات لاحقاً إذا احتجته.
- "تفقيط" المبلغ بالحروف العربية منطق عملي مبسّط وليس محلّلاً نحوياً كاملاً — دقيق للمبالغ العادية لكن يستحق مراجعة يدوية لمبالغ كبيرة جداً أو كسرية معقدة قبل الاعتماد النهائي.
